# 小程序图标与图片兜底修复

## 已确认范围
用户确认按三阶段推进：本阶段先修图标与图片兜底；随后独立推进流式 AI（流式、停止、重试、追问、历史和推荐）；学习记录最后独立立项。本阶段不修改 AI、支付、课程权限或学习数据。

## 根因
原生 TabBar 的四项均无 iconPath / selectedIconPath。首页分类没有本地图标映射，默认资源不存在。收藏、播放器目录及弹幕引用未实现的 iconfont。图片默认路径均没有实际文件。

## 方案
保留原生导航、蓝色主题和现有页面结构。复用仓库已经使用的 Element Plus Icons（MIT），构建时从 SVG 导出本地 PNG，运行时不引入 Vue 或新 UI 库。导航灰色/蓝色双态；分类按 ID 映射代码、咖啡、显示器、书本、增长趋势，未知分类使用网格。收藏、目录、弹幕与我的页操作图标使用同族资源。

图标生成器依赖仅用于工具目录，不进入小程序代码包。PNG 从矢量源生成，透明背景，导航 81×81，其他图标 96×96；保留版权许可。图标明确绑定宽高、与原文字标签一起显示，不以颜色作为唯一的状态说明。

统一图片组件处理搜索、分类、头像、课程封面和空状态。本地兜底必须存在；空值和字符串 null 使用兜底，非空 URL 加载失败只回退一次，兜底失败不再循环加载。回退图片不伪装成真实课程封面或用户头像。课程无介绍视频时显示课程封面，不创建 src 为空的视频。

## 验收接缝
- Node 内置测试：四组导航文件存在且尺寸合规；分类映射稳定、不依赖排序；未知分类有兜底；所有静态图片引用存在；无遗留 iconfont。
- 图片组件状态：真实图片失败后回退；兜底失败不循环；新 src 恢复加载；null/空头像回退。
- 微信开发者工具：编译首页、我的、课程详情及播放器；截图核对分类、四个 Tab 和收藏/弹幕两态；截图成功不能代替自动化断言。当前 automator 响应超时须如实记录，不能称真机验证通过。

## 边界
不重写分类层级，不替换视频原生控件，不接入远程字体。AI 和学习记录分别有自己的规格、计划和验收，不在本次提交中混入。
